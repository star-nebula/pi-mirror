功能地图 / FEATURE MAP

给一个目标，
agent 自己走完研究。

Pi-Mirror 把你的 Markdown 库索引成本地 persona，再给 Studio 一个真实 AgentSession。它自己排计划、查热点、核实说法、读你的笔记、参考高互动帖子、起草、跑 Guard、交付引用齐全的内容包；也能只做问答和单篇起草。

不是固定流水线。工具是固定的，路径由模型在运行时决定。所有能力都在本机运行。

第一次使用

  1. 启动在 pi 里输入 /mirror，浏览器打开它输出的本地地址。
  2. 索引Mirror 空状态点 Index demo vault，或 Ctrl/Cmd K 选 Re-index vault。
  3. 审阅点右上角 You → Persona，点 trait 看证据，Confirm 或 Reject。
  4. 开工Studio 写一个目标（热点、今日方向、改写角度都行），看它自己排计划并调用工具。

之后怎么走

Studio 目标 → 计划与工具轨迹 → 来源与说法判定 → 内容包 → 存 Library → Consent → 记录发布。

整体使用链路

先准备一次，之后把目标交给 Studio；需要时再用 Mirror 单点提问或起草。

第一次

把笔记变成 persona

只做一次。换库或大规模改笔记后再做。

  1. 启动工作台在 pi 里输入 /mirror。浏览器打开它输出的本地地址，默认 127.0.0.1:4317。
  2. 索引笔记Mirror 空状态点 Index demo vault，或 Ctrl/Cmd K 选 Re-index vault。
  3. 审阅 persona点右上角 You → Persona，点 trait 看证据，Confirm 或 Reject。
之后每次

给 Studio 一个目标

热点核实、今日方向、参考爆款改写，都走同一个入口。

  1. 写目标在 Studio 写一句目标，可选平台与受众。目标可以很短，比如「今天 AI 圈有什么值得写」。
  2. 看它排计划agent 先调 update_plan。计划、每一步工具调用、耗时和状态实时写入 run。
  3. 看证据来源按 [n] 编号；说法有 confirmed / single-source / disputed / unverified 判定。
  4. 看它改稿agent 自己调 guard_text，根据 high findings 改，再提交内容包。Guard 哈希必须匹配正文。
  5. 存 Library在内容包点「保存到 Library」，草稿进入本地库；记录发布前先在 Consent 开 publishing。
需要时

Mirror 单点问或写

不跑完整研究，只要一个回答或一篇短稿。

  1. 问Mirror 底部切「问」，问题只从你的笔记里找证据，引用编号可点开。
  2. 写切「写」填 topic、平台、受众、角度；终稿由 submit_draft 交付，再过 Guard。
  3. 查与存「查」可粘贴任意文本；草稿可保存到 Library，发布只记录事实。

常驻导航只有三个入口：Studio、Mirror、Library。Persona、Changes、Consent 收在右上角 You 抽屉里；旧的单功能视图仍可用 #/persona 等深链打开，但不占导航位。顶栏地球按钮在中文 / English 间切换整个工作台，选择会记住。

内部链路

实现细节：一次请求在代码里怎么走。不影响上面的使用顺序。

Studio 运行

POST /api/studio/runs
  1. createRun() 落库 queued，接口立即返回 202 与 run id。同一时间只允许一个 run，第二个返回 429。
  2. startStudio() 新建独立 AgentSession，只挂 13 个 Studio 工具与一段系统提示。
  3. tool_execution_start/end 按 toolCallId 写成编号步骤，并行工具不会互相覆盖。
  4. submit_package 先过 validatePackage()：引用必须在账本内、Guard 哈希匹配正文、无 high findings。通过则存包并把未完成计划标 done；run 结束时仍没有包则记为 error。
  5. 前端轮询 GET /api/studio/run?id=，渲染计划、轨迹、来源、说法与内容包。

检索与核实

web_search · verify_claim
  1. trend_scan 先读本地 demo/trends/*.json，不足再拉 Techmeme RSS。
  2. web_search 抓 Bing HTML，解析 b_algo 结果，并把 bing.com/ck/a 跳转还原成真实域名。
  3. fetch_page 只允许 http/https，解析 DNS 后拒绝 localhost 与私有网段，再抽取正文。
  4. verify_claim 统计独立域名、支持/反驳措辞，给出 confirmed / single-source / disputed / unverified / stale 判定。判定同时喂给 Guard：disputed 会变成 high finding。

索引

POST /api/index
  1. POST /api/index 触发 indexVault()。Markdown 分块，去除 frontmatter，保留 offset。
  2. ensureProfile() 建立默认 Persona profile。
  3. extractTraits() 按规则抽取 value、stance、taboo、goal 与 evidence。
  4. computeVoiceStats() 计算句长、问句率、感叹率、第一人称与列表占比。

问答 · Ask

POST /api/ask
  1. runtime.ask() 抢占 busy 锁，并发请求返回 429。
  2. askPersona() 新建独立的 AgentSession。调用 vault_search、note_read、persona_card。
  3. 全局引用账本为来源编号 [1]…[n]。引用为 0 或密度 < 0.2 时追加一轮 repair。
  4. 写入内存 history，返回 answer + sources + model。

起草 · Write

POST /api/write
  1. composeBrief() 将表单生成英文 brief，再提交 POST /api/write。
  2. draftAsPersona() 新建独立 AgentSession。
  3. 智能体必须调用 submit_draft(markdown) 提交终稿，再由 Guard 检查终稿。
  4. 用户手动保存，POST /api/drafts 写入 drafts 表。

记录发布

POST /api/publish
  1. 用户在 Library 记录发布，提交 POST /api/publish。
  2. 通过 service("consent") 读取授权。Consent 未加载或 publishing=false，返回 403。
  3. 授权通过后写入 publish_records。
  4. 更新 drafts.status = published。只记录已发生的发布，不执行平台发布。

Ask、Write 与每次 Studio run 都建立新的内存会话，不继承对话历史。Studio 的计划与工具轨迹写入 studio_runs / studio_steps；来源与说法判定也随 run 持久化，刷新页面后仍能核对。

运行边界

本机服务、联网研究、授权门禁与笔记写入约束。

安全

  • 服务只绑定 loopback 127.0.0.1。
  • Host 允许列表只接受当前端口的 localhost、127.0.0.1 与 [::1]。
  • CSP 使用 default-src 'self' 与 frame-ancestors 'none'，同时设置 x-frame-options: DENY。
  • 读取笔记检查路径逃逸，不返回 CORS 头。
  • 不存 API key，Ask / Write / Studio 复用 pi 的模型配置。
  • 联网研究只抓公开页面：只允许 http/https，DNS 解析后拒绝 localhost 与私有网段；不向平台发帖。

授权

  • consent_records 只追加，每个 scope 以最新记录为准。
  • 只有 publishing 在服务端强制执行。
  • modeling、drafting、demo 目前只记录，不影响行为。
  • Consent 缺失时按关闭处理，记录发布返回 403。

笔记与发布

  • 不自动发布，不调用平台 API。
  • Studio 保存草稿必须用户点一次；没有 submit_package 的 run 不会变成草稿。
  • 笔记库原文只读，产品不直接修改笔记。
  • 写入请求走 propose_note，形成带 diff 与 hash 校验的提案。
  • 无来源的内容显式标记 [unknown] 或 [inference]；内容包引用不出账本。

实现状态

  • 真实联网研究：Bing 搜索、Techmeme RSS、本地热点包、公开页面抓取与 verify_claim。
  • 参考帖库：互动分、粉丝层级、结构分析与 4-gram 近似改写检测。
  • Ask 与 Write 使用真实 pi AgentSession；中文长查询检索修复、全局引用编号与引用 repair。
  • Persona 证据链与审阅，Guard 七类检查加说法状态检查。
  • 追加式 consent，草稿与发布记录。
  • 37 条测试。源码与构建产物通过 pi RPC 加载，全量与子集组合均已验证。

部分可用

  • Studio 研究只覆盖公开网页；X.com 服务端读不到，热点靠浏览器里记录的 demo/trends 包。
  • 参考帖指标需要手填，不抓平台互动数据；相似度是 4-gram Jaccard，不是语义判定。
  • Timeline 依赖 stance_events，当前演示数据主要显示 observed traits。
  • Trait 审阅 UI 只有确认与拒绝，outdated 仅 API 可用。
  • 发布只记录事实，不校验链接可访问，不拉取平台数据。
  • modeling、drafting、demo 三个 consent scope 只记录，不影响行为。

未实现

  • X / 小红书平台内的结构化检索（当前只有公开网页与手工热点包）。
  • LLM trait 抽取与更大的审阅队列。
  • 脱敏真实库、泄漏扫描与公开只读演示。
  • 评测集，包括引用覆盖、忠实度与个人风格评分。
  • 登录与多用户，当前设计为单机单人。
  • 流式输出、多轮人工改写与平台发布 API。
